AEDT 兩機串接工具包
====================

## 怎麼用

1. 把這個壓縮檔**兩台都**解壓到 `C:\AnsysWork\MpiToolkit`。
2. 雙擊 `一鍵串機.bat`，填另一台的電腦名稱，按「開始」。**兩台各按一次。**
3. 需要逐項操作時才改用 `Run-MpiToolkit-GUI.bat`。

不需要安裝 Python、.NET 或任何相依元件，用 Windows 內建的 PowerShell 5.1。

## 開始之前

| 前提 | 說明 |
|---|---|
| 兩台的 AEDT 版本要**完全一樣** | 連 Service Pack 都要一樣。只看 About 不夠，見 SOP 步驟 1 |
| 要有一個兩台通用的帳號 | 網域環境：同一個網域帳號；工作群組：兩台同名同密碼的本機帳號 |
| 該帳號在兩台都要是**本機系統管理員** | 註冊 MPI 帳密、啟停服務、開防火牆都需要 |
| 該帳號在兩台都要**登入過一次** | 沒有使用者設定檔就註冊不了 MPI 帳密 |
| **不能用 Microsoft 帳戶** | 密碼在雲端，兩台無法設成一致，MPI 跨機認證過不去 |

## 最容易漏掉的一步

**MPI 帳密要在每一台各自註冊一次，而且要互動登入那台再執行。**

漏了的症狀：求解卡在「Determining memory availability on distributed machines」
完全不動，**而且不會跳任何錯誤訊息**。

只驗證單向（A→B）會得到假的通過——求解時 MPI 跑在哪一台不由你決定。
詳見「說明文件\串機排錯指南.md」。

## 檔案

### 入口（雙擊執行）
- `一鍵串機.bat` —— 九步精靈，現場主要用這個
- `指定機組啟動器-範本.bat` —— 固定機組用，填入兩台機器名稱後兩台各雙擊一次
- `執行串機檢查.bat` / `Run-ClusterCheck.bat` —— 只做檢查不修改
- `執行診斷.bat` —— 出問題時收集現場資料
- `Run-MpiToolkit-GUI.bat` —— 圖形介面，逐項操作
- `Run-LicenseCheck.bat` —— 授權檢查

### 腳本
- `Start-OneClickCluster.ps1`、`MpiToolkit-GUI.ps1`
- `Test-AedtCluster.ps1` —— 節點檢查與兩台彙整
- `Repair-AedtClusterNode.ps1` —— 自動修復
- `New-AedtClusterConfig.ps1` —— 產生 AEDT 機器清單
- `Register-IntelMpiCredential.ps1` —— MPI 帳密註冊
- `Check-AnsysLicense.ps1`

### 說明文件\
- `現場串機SOP.md` —— **網域**環境，九步，每步附驗收
- `現場串機SOP-無網域.md` —— **工作群組**環境
- `串機排錯指南.md` —— 出事時按症狀查
- `為何關閉Domain Solver.md` —— 給客戶看的配置說明
- `現場一鍵串機操作卡.md` —— 精靈的逐步操作卡
- `客戶端操作與驗證.md`
- `START_HERE.html` —— 圖文版設定指南

## 安全性

- 工具不接收、不儲存密碼，也不把密碼放進命令列或報告。
  MPI 帳密由 Intel 原生的 `mpiexec -register` 自己收，工具只負責叫它起來。
- 防火牆規則只開必要的埠，只允許 LocalSubnet，**不會關閉 Windows 防火牆**。
- 修改 `default.cfg` 前會自動備份。
- 報告會遮蔽機器名稱與使用者名稱。
