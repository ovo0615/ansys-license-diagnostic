# AEDT 串機排錯指南

按「你看到什麼」找，不要按「你猜是什麼」找。

**共通原則**：這類問題**幾乎都不會跳錯誤訊息**，只會停住。所以判斷「是不是卡住」
要看客觀證據，不要看進度列。

---

## 怎麼判斷「真的卡住」而不是「在算」

同時滿足下面三項就是卡住：

| 證據 | 卡住時 | 在算時 |
|---|---|---|
| 求解暫存目錄的檔案時間戳 | 幾分鐘沒動 | 持續更新 |
| 求解行程的記憶體 | 完全不變 | 會變動 |
| 求解行程的執行緒數 | 1（設定卻是多核） | 與設定的核心數相符 |

**CPU 100% 不代表在算。** Intel MPI 預設 busy-wait，兩端互等時一樣吃滿一顆核心。

```powershell
# 對端（B 換成對端名稱）
Get-WmiObject Win32_Process -ComputerName B |
  Where-Object Name -match 'hf3d|matrix_solution|HFSSCOMENGINE|mpiexec|hydra' |
  Select-Object Name, ProcessId, ThreadCount, @{n='RAM_MB';e={[math]::Round($_.WorkingSetSize/1MB)}}
```

## 症狀對照表

### 卡在「Determining memory availability on distributed machines」

**最常見的原因：某一台沒有註冊 MPI 帳密。**

分散求解時 `mpiexec` 是跑在**被指派工作的那一台**，不一定是你按 Analyze 的那台。
帳密存在執行者自己的 `HKCU\Software\Intel\MPI`，少任何一台都會卡住。

確認方法——在**每一台**上跑：

```powershell
$mpi = 'C:\Program Files\ANSYS Inc\v261\AnsysEM\common\fluent_mpi\multiport\mpi\win64\intel21\bin\mpiexec.exe'
& $mpi -validate
```

沒註冊時會看到：

```
HYD_win_read_credentials (hydra_registry.c:205): Unable to open registry key, error: 0
unable to send credentials to service
```

處理：以該帳號**互動登入那一台**，執行 `& $mpi -register`。

> 遠端執行（WMI、PsExec、排程）不會載入該使用者的設定檔，寫不進去。
> 帳號在那台連使用者設定檔都沒有時更是如此。

其他可能原因，依可能性排序：

| 原因 | 怎麼確認 |
|---|---|
| 兩台版本不一致 | 步驟 1 的逐檔比對 |
| 對端沒設 `ANSYS_EM_EXEC_DIR` | `Get-WmiObject Win32_Environment -ComputerName B` |
| 回連位址挑到虛擬網卡 | 看引擎命令列裡的 `IPAddress=` |
| 防火牆沒放行回連埠 | 看對端有沒有 ESTABLISHED 連線回來 |

### 引擎拿到錯的回連位址

看對端引擎的完整命令列：

```powershell
Get-WmiObject Win32_Process -ComputerName B | Where-Object Name -match 'COMENGINE' |
  ForEach-Object { $_.CommandLine }
```

裡面有 `IPAddress='...'` 與 `ListenPort='...'`。位址如果是 `172.x` 或其他對端
到不了的網段，就是 AEDT 挑到了虛擬介面。

處理：**停用該虛擬介面**（`Disable-NetAdapter`），不是改 Metric。
改 Metric 實測無效。

---

### `Auto Select Direct/Iterative solver option is not supported by Manual HPC Settings`

改成手動 HPC 設定之後就不能讓矩陣求解器自動選。

處理：Setup 右鍵 → Properties → Options → Solver → 改成 **Direct Solver**。

---

### 跑得起來，但卡在矩陣求解（Solving matrix）

前面的步驟都過了、自適應網格也跑了好幾次 pass，卡在 `Solving matrix part n of m`。

原因：**開著 Domain Solver，在一般乙太網路上跨機解同一個矩陣**。

處理：HPC Options → Distribution Types → 取消 Domain Solver，保留 Frequencies。
詳見〈為何關閉 Domain Solver〉。

---

### 裝了 Service Pack，但版本沒變

安裝程式可能宣告 `Installation Complete` 卻**沒有真的解壓**該產品。

確認：

```powershell
Select-String -Path 'C:\Program Files\ANSYS Inc\install.log' -Pattern 'Start Installation|Service Pack To Install|Extraction:|Installation Complete:' |
  Select-Object -Last 40
```

- 有 `Service Pack To Install: N` 但**沒有任何 `Extraction:` 行** → 那一場什麼都沒裝
- 有 `Extraction:` 但停在某一個檔案 → 中途被中斷

也要看產品自己的版本檔（這個才是真的）：

```powershell
Get-Content 'C:\Program Files\ANSYS Inc\v261\AnsysEM\product.info'
```

處理（依序嘗試）：

1. 關掉 AEDT，重跑 `setup.exe`，**中途不要中斷**
2. 還是沒變 → 從「設定 → 應用程式」解除安裝 Electromagnetics Suite 與
   Electromagnetics RSM，再重裝
3. 趕時間的非正規做法：用安裝包自帶的 `util\7zip\7z.exe` 把
   `<SP>_electromagneticssuite\EM_SBO\WINX64.7z` 直接解壓覆蓋到 AnsysEM 目錄

> 做法 3 若遇到「Cannot delete output file」，代表該 DLL 被行程載入中
> （常見是 PyAEDT／MCP 的 python）。把檔案**改名**（已載入的 DLL 不能刪但可以改名）
> 再解壓即可，不必砍行程。

### 綁不到埠 / WSAEACCES / 10013

Windows 有一段保留的 TCP 埠，落在裡面就綁不到：

```powershell
netsh int ipv4 show excludedportrange protocol=tcp
```

處理：把 `ANSYSEM_LISTEN_PORT_RANGE` 與 `I_MPI_PORT_RANGE` 改到保留範圍之外。

---

### 遠端桌面連不上要設定的那台

```powershell
(Get-WmiObject -Namespace root\CIMV2\TerminalServices -Class Win32_TerminalServiceSetting -ComputerName B).AllowTSConnections
```

回 `0` 就是停用中。開啟需要對方同意——這是動別人電腦的安全性設定。
臨時開啟的話，**收尾時要記得關回去**。

## 清掉殘留行程

求解卡住中止之後，對端常會留下孤兒行程，不清掉會影響下一次。

```powershell
Get-WmiObject Win32_Process -ComputerName B |
  Where-Object { $_.Name -match 'HFSSCOMENGINE|mpiexec|hydra_bstrap|hydra_pmi|hf3d' } |
  ForEach-Object {
      $owner = ($_.GetOwner()).User
      "$($_.Name)  PID $($_.ProcessId)  $owner"
  }
```

**只清掉屬於自己那個帳號的**。對端可能是同事的機器，上面有他自己的 AEDT 在跑。

## 現場最常犯的三個錯

1. **只驗證單向 MPI。** A→B 通不代表 B→A 通，而求解用的是哪個方向不由你決定。
2. **在錯的機器上執行指令。** `mpiexec -validate` 第一行印出的主機名稱就是你所在的
   機器，先看那個。
3. **相信「Installation Complete」。** 要看檔案的版本與日期，不要看安裝程式的宣告。
