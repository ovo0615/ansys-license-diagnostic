# 客戶端操作與驗證

## 前置需求

| 項目 | 要求 |
| --- | --- |
| 作業系統 | Windows 10／11 或 Windows Server，內建 Windows PowerShell 5.1 |
| 權限 | 建議以系統管理員身分開啟 PowerShell |
| 安裝套件 | 不需要安裝 Python、PowerShell 7 或其他套件 |
| 工具位置 | 每台都把完整工具資料夾複製到 `C:\AnsysWork\MpiToolkit` |
| 路徑 | Ansys 專案、工具、報告與暫存路徑全部使用 ASCII，不得含中文 |
| 測試模型 | 使用幾分鐘內能完成的小模型複本，不要直接操作客戶原始專案 |

以下範例假設兩台電腦名稱為 `WS01` 與 `WS02`。先在每台執行 `hostname`，換成實際名稱。

## 今天：兩台同事電腦驗證

### 1．先跑離線測試

在任一台電腦的系統管理員 PowerShell 執行：

```powershell
Set-Location C:\AnsysWork\MpiToolkit
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\tests\Run-AllTests.ps1
```

通過標準：最後顯示「4 組測試全部通過」，離開代碼為 `0`。

### 2．兩台互相檢查

WS01：

```powershell
Set-Location C:\AnsysWork\MpiToolkit
.\Run-ClusterCheck.bat -CaseId INTERNAL-20260909 -Peers WS02 -Mode DDM -Json -OutDir C:\AnsysWork\MpiToolkit\reports_raw
```

WS02：

```powershell
Set-Location C:\AnsysWork\MpiToolkit
.\Run-ClusterCheck.bat -CaseId INTERNAL-20260909 -Peers WS01 -Mode DDM -Json -OutDir C:\AnsysWork\MpiToolkit\reports_raw
```

通過標準：

| 檢查 | 通過條件 |
| --- | --- |
| AEDT | 兩台都有準備使用的相同版本 |
| RSM | 服務為 `Running`，TCP 32958 有監聽 |
| MPI | 兩台偵測到相同種類與版本；DDM 必須有 MPI |
| 作業系統 | 兩台 Windows 名稱、版本與更新層級一致 |
| 對端 | 名稱解析成功，TCP 32958 顯示 `OK` |
| temp | 路徑字串相同，但各自指向本機磁碟 |
| 網路 | 兩台位於預期網段；多網卡或 VPN 必須確認實際使用介面 |

### 3．彙整兩台報告

用檔案總管把兩台 `reports_raw` 內的 `*.node.json` 複製到同一個資料夾：
`C:\AnsysWork\MpiToolkit\merge_input`。不要改檔案內容。

```powershell
Set-Location C:\AnsysWork\MpiToolkit
.\Run-ClusterCheck.bat -Merge C:\AnsysWork\MpiToolkit\merge_input -Json -OutDir C:\AnsysWork\MpiToolkit\merged_raw
```

通過標準：沒有「案件編號不一致」、「沒有共通 AEDT 版本」、「RSM 沒有執行」、
「沒有共同 MPI」或「連線測試失敗」等【確定】項目。

### 4．確認實際使用的 MPI

在兩台使用實際執行 AEDT 的同一個 Windows 帳號登入，分別執行：

```powershell
Get-Command mpiexec.exe -All -ErrorAction SilentlyContinue
mpiexec.exe -help
```

一般 Windows 多工作站在 AEDT 的 `HPC and Analysis Options > Options` 選擇
`MPI Vendor = Intel`，`MPI Version = Default` 或兩台共同安裝的版本。Microsoft MPI
多主機只支援 Windows HPC Job，不是一般工作站或 VPN 的替代方案。

不同 Intel MPI 版本的驗證方式可能不同。依 `mpiexec.exe -help` 與該版本文件處理；
不要把帳號密碼寫入命令、報告或文件，也不要直接沿用舊版 SOP 的
`mpiexec -register/-validate`。

### 5．另外產生並驗證可外傳的匿名報告

兩台都再執行一次，輸出到 `reports_anonymized`；案件編號只用代碼，不要包含客戶名稱：

```powershell
.\Run-ClusterCheck.bat -CaseId SHARE-20260909 -Peers WS02 -Mode DDM -Json -Anonymize -OutDir C:\AnsysWork\MpiToolkit\reports_anonymized
```

匿名化報告中的主機名稱已雜湊，不能拿來產生實際串機設定。`reports_raw` 只留在現場，
不得寄出；需要回傳時只使用 `reports_anonymized`。

驗證匿名化：

在每台產生報告後執行：

```powershell
$needles = @($env:COMPUTERNAME, $env:USERNAME)
$privateIps = Get-NetIPAddress -AddressFamily IPv4 -ErrorAction SilentlyContinue |
    Where-Object { $_.IPAddress -match '^(10\.|192\.168\.|172\.(1[6-9]|2[0-9]|3[01])\.)' } |
    Select-Object -ExpandProperty IPAddress
$patterns = @($needles + $privateIps | Where-Object { $_ } | ForEach-Object { [regex]::Escape($_) })
Get-ChildItem C:\AnsysWork\MpiToolkit\reports_anonymized -File |
    Select-String -Pattern $patterns -SimpleMatch:$false
```

通過標準：沒有輸出。若列出任何檔案與行號，不要把該報告寄出。

### 6．選做：製造一個安全的失敗案例

不要停服務。把 `-Peers` 暫時改成不存在的 `NO-SUCH-HOST-TEST` 再跑一次。
通過標準：報告應明確出現名稱無法解析，不能顯示為正常。

## 明天：客戶端執行

### 1．先做唯讀檢查

1. 取得客戶同意後，把完整工具複製到每台的 `C:\AnsysWork\MpiToolkit`。
2. 以系統管理員身分開啟 PowerShell。
3. 使用同一個、不含客戶名稱的案件編號，在每台執行「兩台互相檢查」的命令。
4. 原始報告只留在客戶端，用來彙整與產生 machine list。
5. 需要回傳時另外加上 `-Anonymize` 重跑，並執行匿名化驗證。
6. 收齊原始 `.node.json` 後執行彙整。

授權只做唯讀檢查時：

```powershell
Set-Location C:\AnsysWork\MpiToolkit
.\Run-LicenseCheck.bat -CaseId CUSTOMER-20260910 -NoCheckout -Json -Anonymize -OutDir C:\AnsysWork\MpiToolkit\license_reports
```

`-NoCheckout` 不會實際取用授權。要驗證特定產品授權時，必須先確認正確的
FlexNet feature，再移除 `-NoCheckout`；不要在客戶工作尖峰時段嘗試未知 feature。

### 2．產生設定，但先不要送出求解

只有彙整結果通過後才執行：

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\New-AedtClusterConfig.ps1 `
    -From C:\AnsysWork\MpiToolkit\merge_input `
    -Project C:\AnsysWork\MpiTest\SmallModel.aedt `
    -OutDir C:\AnsysWork\MpiToolkit\cluster_config
```

先閱讀 `待辦清單.txt`，再執行 `verify-batchoptions.cmd`。它會使用 `-Help` 與
`-Batchoptionhelp` 核對該 AEDT 版本的
`-BatchSolve`、`-Distributed` 與 `-MachineList` 選項。`run-batch.cmd` 的求解命令預設被註解；
未核對選項前不得解除註解。

### 3．實際求解驗證

| 步驟 | 驗證方法 |
| --- | --- |
| 單機基準 | 先用小模型複本單機求解，記錄完成時間與結果 |
| 分散求解 | 使用相同模型與設定啟動兩台求解 |
| GUI 預檢 | 在 Analysis Configuration 的 Machines 頁執行 `Test Machines` |
| 確認真的分散 | 在兩台工作管理員確認求解程序與 CPU／記憶體都有活動 |
| 結果一致 | 比對求解完成狀態與主要結果；不得只看命令回傳成功 |
| 效能 | 記錄單機與雙機時間；雙機較慢不等於設定錯誤，DDM 對網路延遲敏感 |

若 AEDT 已開啟，測試完成後保留視窗供客戶檢查。不要用 `taskkill` 關閉 AEDT 或求解程序；
需要停止求解時使用 AEDT 的取消分析功能。

防火牆正式設定必須保持啟用，並放行 AEDT、RSM、Intel Hydra 與 MPI 所需通訊埠。
暫時停用防火牆只可作為特定連線錯誤的隔離測試，確認後立即恢復。

## 現場失敗時帶回什麼

| 必帶資料 | 注意事項 |
| --- | --- |
| 每台的 `.txt`、`.node.json`、`.findings.json` | 必須先通過匿名化驗證 |
| 彙整報告 | 保留案件編號一致性 |
| `hostname` 與 Windows／AEDT 版本 | 不確定是否能外傳時只記錄在現場筆記 |
| RSM、MPI 服務狀態 | 不要記錄帳號密碼 |
| `verify-batchoptions.cmd` 顯示結果或截圖 | 截圖前遮蔽客戶名稱、路徑與主機名稱 |
| 單機／雙機求解時間與錯誤訊息 | 記錄錯誤全文，不要只寫「失敗」 |
