# 串機工具　現場驗證清單

`Test-AedtCluster.ps1` 與 `New-AedtClusterConfig.ps1` 有一半的行為
**無法在開發機驗證**——要讀 Windows 的服務、登錄檔、網卡、防火牆，
還要有真的 AEDT 安裝。這份清單是第一次帶去客戶端（或自家測試機）時要逐項核對的東西。

**建議先在自家的兩台 Windows 機器上跑完 A、B 兩段，再帶去客戶端。**
在客戶端才發現偵測邏輯有問題，比沒帶工具去還糟。

驗證完請把結果填回這份文件並提交，下一個人才不用重做。

| 狀態記號 | 意義 |
| --- | --- |
| ☐ | 未驗證 |
| ☑ | 已驗證，行為正確 |
| ✗ | 已驗證，行為錯誤（請在該項下方寫實際情況） |

## A. 節點收集模式（`Test-AedtCluster.ps1` 不加 `-Merge`）

在一台裝有 AEDT 的 Windows 機器上，**以系統管理員身分**執行：

```powershell
.\執行串機檢查.bat -CaseId VERIFY-001
```

然後打開產生的 `.txt` 報告，逐項核對。

### A1　AEDT 安裝偵測　☐

報告的「AEDT 安裝」一節應該列出這台**實際安裝的每一個版本**。

核對：

- [ ] 版本代號翻譯正確（`v242` → `2024 R2`、`v251` → `2025 R1`）
- [ ] 安裝路徑正確
- [ ] 「偵測來源」有列出 `env` / `registry` / `filesystem` 至少一種
- [ ] 多版本共存時每個版本都被找到，且**沒有重複列出同一個**

> 已知風險：`ANSYS Inc` 與 `Ansys Inc` 在 Windows 是同一個目錄。
> 診斷工具踩過這個坑（每個版次被偵測兩次），串機工具的去重是用小寫路徑當 key，
> 理論上不會，但要實際確認。

若某個版本沒被找到，記下它的安裝路徑與登錄檔位置，`Get-AedtInstalls` 要補。

### A2　`default.cfg` 與 temp 目錄　☐

- [ ] 報告列出的 `default.cfg` 路徑確實存在
- [ ] `tempdirectory` 的值與檔案內容相符
- [ ] 檔案裡**沒有**這一行時，報告顯示「(未設定，使用內建預設)」而不是空白或報錯

實際確認檔案內容：

```powershell
Get-Content "C:\Program Files\AnsysEM\v242\Win64\config\default.cfg" | Select-String tempdirectory
```

> 這一項的解析用的是 `^\s*tempdirectory\s*=\s*["']?([^"'\r\n]+)["']?\s*$`。
> 若客戶的檔案用了別的寫法（例如行尾有註解），要把樣式放寬。

### A3　RSM 服務偵測　☐

- [ ] 報告的服務名稱與 `Get-Service | Where-Object { $_.Name -match 'RSM' }` 一致
- [ ] 服務在跑時報【正常】，停掉時報【確定】RSM 服務已安裝但沒有執行
- [ ] `netstat -ano | findstr 32958` 有監聽時，報告不會出現「沒有在聽」的【可疑】

實際比對：

```powershell
Get-Service | Where-Object { $_.Name -match 'RSM' -or $_.DisplayName -match 'RSM' } | Format-Table Name, DisplayName, Status
netstat -ano | findstr 32958
```

> **這一項是設計文件第七節的第 4 項。** 2023 R1 之後 RSM 的服務名稱可能變了。
> 工具用的是樣式比對（名稱或顯示名稱含 `RSM`）而不是寫死，理論上換名也抓得到，
> 但要確認新版真的還有這個服務。

### A4　MPI 偵測　☐

- [ ] Intel MPI：`hydra_service` 有裝時被抓到，版本號正確
- [ ] Microsoft MPI：有裝時被抓到（服務 `MsMpiLaunchSvc` 或登錄檔 `HKLM\SOFTWARE\Microsoft\MPI`）
- [ ] 沒有任何 MPI 服務時，報告是【可疑】而不是【確定】
- [ ] `-Mode DSO` 時，沒有 MPI 不會被列為問題

實際比對：

```powershell
Get-Service | Where-Object { $_.Name -match 'hydra|MsMpi|MPI' } | Format-Table Name, DisplayName, Status
Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\MPI' -ErrorAction SilentlyContinue
```

> **這是設計文件第七節的第 3 項。** 要確認的是：近版 AEDT 安裝時
> 是否已經把 Intel MPI 與 `hydra_service` 一起裝好。
> 若是，「沒偵測到 MPI」的嚴重度可以往上調；若否，維持【可疑】。

另外核對「AEDT 內附的 MPI 執行檔」一節有沒有列出東西——
它掃的是 `<安裝路徑>\common\mpi\*\*\hydra_service.exe` 之類的路徑，
實際目錄結構若不同要修樣式。

### A5　網路介面與網段　☐

- [ ] 報告列出的介面與 `Get-NetIPConfiguration` 一致
- [ ] Hyper-V / VMware / VPN 介面有被標記為 `[虛擬／VPN]`
- [ ] 網段計算正確（例如 `192.168.10.13/24` → `192.168.10.0/24`）
- [ ] 只有一張實體網卡時，不會出現「多個實體網路介面」的【可疑】

> 虛擬介面的判定靠名稱樣式比對。客戶環境若有本工具認不出的虛擬介面
> （某些 VPN 用戶端、SDN 網卡），把它的 `InterfaceDescription` 記下來加進
> `Get-ActiveAdapters` 的 `$virtualPattern`。

### A6　防火牆　☐

- [ ] 三個設定檔（Domain / Private / Public）的開關狀態正確
- [ ] 有放行 32958 的規則時，報告的「與串機相關的輸入防火牆規則」列得出來
- [ ] 一般權限執行時，讀不到防火牆會報【需人工】而不是報「沒有規則」

> `Get-NetFirewallPortFilter` 在規則多的機器上可能很慢。
> 若執行時間明顯拉長（超過 30 秒），要改成只查特定埠。**請記錄實際耗時。**

### A7　對端連通性　☐

需要第二台機器。在 WS01 上：

```powershell
.\執行串機檢查.bat -CaseId VERIFY-001 -Peers WS02
```

- [ ] WS02 的 RSM 有跑時，報告顯示 TCP 32958 OK
- [ ] 把 WS02 的 RSM 停掉重跑，報告出現【確定】連不上
- [ ] 故意打錯機器名，報告出現【確定】名稱無法解析
- [ ] TCP 測試的逾時（預設 3 秒）在客戶網路下夠用

### A8　權限不足時的行為　☐

以**一般使用者**（非管理員）身分跑一次：

- [ ] 不會整支崩掉
- [ ] 讀不到的東西報【需人工】並註明「權限不足，結果不可信」
- [ ] **不會**因為讀不到服務就宣稱「沒有安裝 RSM」

> 這一項很重要。工具的核心承諾是「不敢斷言的事就不斷言」，
> 權限不足時亂報【確定】會直接違反這個承諾。

### A9　執行時間　☐

- [ ] 單台收集在 ______ 秒內完成（記錄實際值）

客戶不會等一支跑五分鐘的檢查工具。超過 60 秒就要找出是哪一段慢。

## B. 彙整模式（`-Merge`）

彙整模式已有 40 項自動測試，但那些用的是合成資料。
用 A 段產生的**真實** `.node.json` 再跑一次：

```powershell
.\執行串機檢查.bat -Merge .\reports
```

### B1　真實資料不會讓彙整壞掉　☐

- [ ] 能正常讀入所有 `.node.json`
- [ ] 「各節點摘要」表格對齊沒有跑掉（中文全形字在等寬字體下的寬度問題）
- [ ] 結論與 A 段各台的實際狀況相符

### B2　刻意製造差異　☐

把兩台弄成不一致，確認工具講得出來：

- [ ] 兩台的 `tempdirectory` 改成不同值 → 出現【確定】temp 目錄各機路徑不同
- [ ] 一台停掉 RSM → 出現【確定】，且 `fixOn` 指向那一台
- [ ] 兩台裝不同版本 → 出現【確定】沒有共通版本，**且 temp 的差異仍然被講出來**

最後一項是實作時修過的坑，要確認修對了。

## C. 設定產生器（`New-AedtClusterConfig.ps1`）

```powershell
.\New-AedtClusterConfig.ps1 -From .\reports -Project D:\work\test.aedt
```

### C1　`-MachineList` 的實際語法　☐

**這是最重要的一項，也是唯一擋住工具真正可用的東西。**

1. 跑產生器輸出的 `verify-batchoptions.cmd`（會開一個 GUI 對話框）
2. 對照下列每一個選項是否存在、拼法是否相同：

| 工具產生的寫法 | 實際版本的寫法 | 相同？ |
| --- | --- | --- |
| `-ng` | | ☐ |
| `-BatchSolve` | | ☐ |
| `-Distributed` | | ☐ |
| `-MachineList file="..."` | | ☐ |
| `-MachineList list="host:tasks:cores:90%"` | | ☐ |

3. 確認 `list=` 每台的四個欄位順序真的是
   `主機:每節點task數:每節點核心數:使用率上限`

**把實際看到的選項清單截圖存檔**，這是之後所有版本判斷的依據。

### C2　實際跑一次批次求解　☐

用一個小模型（幾分鐘能算完的），把 `run-batch.cmd` 的 `REM` 拿掉：

- [ ] Form A（`file=`）能跑起來
- [ ] Form B（`list=`）能跑起來
- [ ] 求解真的分散到多台（工作管理員看得到另一台的 CPU 上去）
- [ ] `%%` 跳脫在實際執行時被正確解讀成一個 `%`

> 最後一項單獨確認：在 `run-batch.cmd` 裡加一行
> `echo -MachineList list="WS01:1:16:90%%"`，看螢幕印出來的是不是
> `list="WS01:1:16:90%"`（一個百分號）。

### C3　`.acf` 的實際結構　☐

- [ ] 在 GUI 的 `HPC and Analysis Options` 設定好一組組態
- [ ] machine list 分頁能匯入產生器輸出的 `machines.txt`
- [ ] 匯出成 `.acf`
- [ ] **把這份 `.acf` 帶回來**（去識別化後）放進 `docs/samples/`

拿到真實範本之後，產生器才有條件自動產生 `.acf`。
在那之前不要猜——猜錯會靜默套用錯誤設定，比沒有更難查。

## D. PowerShell 5.1 實機執行

開發與 CI 都是在 PowerShell 7 上跑的。5.1 的相容性只做了**語法**檢查
（`tools/Check-Ps51Compat.ps1`），行為差異查不到。

在 Windows 內建的 PowerShell 5.1（**不是** 7.x）上：

```powershell
$PSVersionTable.PSVersion    # 確認是 5.1.x
.\執行串機檢查.bat -CaseId VERIFY-001
.\tests\Run-AllTests.ps1
```

- [ ] 中文顯示正常（不是亂碼）——這驗的是 UTF-8 BOM 有沒有生效
- [ ] 節點收集能完成
- [ ] 彙整模式能完成
- [ ] `tests\Run-AllTests.ps1` 在 5.1 上也全通過

已知的 5.1 行為差異風險（語法檢查抓不到，要實測）：

| 風險 | 為什麼 |
| --- | --- |
| `ConvertTo-Json` 的預設深度 | 5.1 預設 2，本工具都有明寫 `-Depth`，但要確認輸出沒被截斷 |
| `ConvertFrom-Json` 對空陣列 | 5.1 可能回 `$null` 而不是空陣列；程式碼都有 `@()` 包起來，要確認 |
| `Get-CimInstance` 的可用性 | 5.1 有，但舊版 Windows Server 上要確認 |
| `Out-File -Encoding utf8` | 5.1 會寫出 **帶 BOM** 的 UTF-8，7.x 不帶。報告檔用文字編輯器打開確認 |
| `[System.Net.IPAddress]::new()` | 5.1 支援 `::new()`，但要實測 |

**最後一項特別注意**：`Get-NetworkKey` 已經因為 `[uint32]0xFFFFFFFF -shl n`
在 7.x 上靜默失效過一次。5.1 的數值轉型行為可能又不同，
請實際確認報告裡的網段值是對的，不是 null。

## E. 沒有做、也不打算在這個階段做的事

列出來是為了避免下一個人以為漏掉了：

| 項目 | 為什麼不做 |
| --- | --- |
| MPI 帳密是否註冊過 | 憑證在使用者層級，工具不去讀也不應該讀。只請人自己跑 `mpiexec -validate` |
| 時鐘偏移比對 | 各節點在不同時間收集，事後無法還原偏移；要做得靠遠端 WMI，代價不划算 |
| 網路頻寬與延遲實測 | 要實際送流量，違反唯讀原則。DDM 划不划算請用真實模型測 |
| 自動停用多餘網卡 | 會影響其他軟體，屬 Tier 3，永不自動化 |
| `Initialize-AedtCluster.ps1`（會改機器的佈署工具） | 要等 A～D 驗證完，確認偵測邏輯是對的，才有資格去改客戶的機器 |
