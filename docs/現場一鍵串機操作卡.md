# 現場一鍵串機操作卡

## 照抄這個

```
1. 兩台都解壓工具到 C:\AnsysWork\MpiToolkit
2. 兩台都建一個叫 ansys 的帳號，密碼設成同一組，都用它登入
3. A 台 → 雙擊「一鍵串機.bat」→ 填 B 台的電腦名字 → 按「開始」
4. B 台 → 雙擊「一鍵串機.bat」→ 填 A 台的電腦名字 → 按「開始」
5. 回 A 台 → 再按一次「開始」
```

**總共按三次，做完就好。** 下面是為什麼，以及卡住的時候怎麼辦。

不用裝 Python，不用裝任何套件。用 Windows 內建的 PowerShell 5.1。

---

## 為什麼要按三次

**因為工具要比對兩台，而它一次只看得到一台。**

像兩個人各自去體檢。第一個人抽完血，報告還不能出——要等第二個人也抽完，
兩份放在一起，才比得出「你們兩個哪裡不一樣」。

版本不一樣、安裝路徑不一樣、暫存資料夾不一樣、網段不一樣——
這些單機自己看永遠看不出來。

所以 A 台第一次按下去會跑到第 4 步停住，畫面上寫**「等待對端」**。
這是正常的，不是壞掉。去 B 台按一次，回來再按一次，就會自己接下去跑完。

---

## 電腦的名字去哪裡看

對方那台的**設定 → 系統**，最上面那一行就是。

打不出來就填 IP，工具兩種都吃。

---

## 螢幕上那九行是什麼

不用背。跑的時候每一行前面會出現一個符號：

| 符號 | 意思 |
|---|---|
| ✓ | 過了 |
| △ | 過了，但有事情要看一下 |
| … | 在等另一台，去按另一台 |
| ✗ | 卡住了，**看這一行下面寫什麼** |

**只有 ✗ 需要你動作。** 下面的黑框會告訴你卡在哪、要做什麼。

九行在做的事，以及卡住時先查什麼：

| 第幾步 | 在做什麼 | ✗ 的時候先查 |
|---|---|---|
| 1 | 看你的帳號、AEDT 裝了沒、有沒有權限 | 帳號是不是 Microsoft 帳戶（見下一節） |
| 2 | 看得不看得到另一台 | 名字打不出來就改填 IP |
| 3 | 檢查這一台自己 | — |
| 4 | 跟另一台交換檢查結果 | 「等待對端」是正常的，去另一台按一次 |
| 5 | 比對兩台哪裡不一樣 | 版本或安裝路徑不一樣要先弄成一樣 |
| 6 | 修設定（會跳出視窗問你要不要，按「是」） | **兩台都要各跑一次才算數** |
| 7 | 輸入 MPI 帳號密碼 | 見下一節 |
| 8 | 真的試一次兩台能不能一起工作 | 沒過通常是密碼不一樣 |
| 9 | 產生機器清單 | 只有主控那台會做 |

第 6 步實際上改了這些：把兩台的暫存資料夾統一成 `C:\AnsysWork\AedtTemp`
（會先備份原本的 `default.cfg`）、設定 RSM 需要的 `ANSYS_EM_EXEC_DIR`、
啟動 RSM 與 Intel Hydra 服務、開防火牆規則（只放行同網段，不會關防火牆）。

---

## MPI 的帳號密碼打誰的

**打你自己這台的帳號密碼。但兩台的帳號名字跟密碼必須一模一樣。**

這兩句不矛盾，因為那本來就是同一組。想像鑰匙：

> 你在 A 台輸入帳密，等於告訴 A 台「我的鑰匙長這樣」。A 台把它收在抽屜裡。
>
> 要叫 B 台幫忙算的時候，A 台會**把你那把鑰匙複製一份寄過去**。
>
> B 台拿這把鑰匙去開**自己家的門**。開得了，才會幫你算。

所以問題不是「打誰的」，是**B 家的鎖吃不吃這把鑰匙**。

兩台帳號名字跟密碼一樣 → 同一把鑰匙兩邊都開得了 → 成功。
一台叫 `admin`、一台叫 `user` → 鑰匙插不進去 → 失敗。

**絕對不要打對方那台的帳密。** 視窗問的是「你是誰」，不是「你要去哪」。

### 最坑的地方：註冊成功不代表能用

按下註冊的時候，電腦只是把鑰匙放進抽屜，**沒有人跑去試開門**。
所以它一定會說成功，就算兩台的鎖根本不一樣。

真正去試開門的是**第 8 步**。第 8 步過了才是真的過。

### Microsoft 帳戶一定不行

**因為它的密碼不在你手上，在微軟的伺服器上。**

你沒辦法把兩台的密碼「設成一樣」——那不是你能設的東西。這種鑰匙複製不出來。

工具第 1 步就會擋下來，直接告訴你要改。要自己先看的話：

| 看哪裡 | 合格的樣子 |
|---|---|
| 設定 → 帳戶 | 顯示「本機帳戶」，不是一個 email |
| 兩台的帳號名字 | 一個字都不差 |
| 兩台的密碼 | 一個字都不差（**工具驗不到，只能你自己確認**） |

不合格的話，兩台各做一次：

```
設定 → 帳戶 → 其他使用者 → 新增帳戶
→「我沒有這位人員的登入資訊」
→「新增沒有 Microsoft 帳戶的使用者」
→ 帳號名字與密碼兩台一個字都不差，權限選「系統管理員」
→ 兩台都改用這個帳號登入，再跑工具
```

### 改過密碼會突然壞掉

抽屜裡那把是**你改密碼當天存進去的那一把**。你改了 Windows 密碼，
抽屜裡的不會跟著換。

症狀是「昨天還好好的，今天突然串不起來」。**解法：重跑一次第 7 步。**

---

## 順手的判斷法

**第 2 步如果說「看不到另一台的 C$」，先懷疑帳號，不要先懷疑網路。**

Windows 要讓你看到另一台的 `C$`，用的是同一套帳密比對。
帳號名字或密碼不一樣，這裡就會不通——跟 MPI 失敗是同一個原因。

所以這個訊息其實是在提前告訴你第 8 步會掛。

---

## 跑完之後

東西在 `oneclick\PAIR-兩台名字\out\cluster-config\`。

**工具不會自己開始算。** 要真的開始算之前還有三件事要人做：

1. 先跑一次 `verify-batchoptions.cmd`
2. **只在主控那台開 AEDT**，另一台只留 RSM 跟 Intel Hydra 服務在背景，其他都不要開
3. AEDT 裡按一次 **Test Machines**

### 為什麼求解指令是註解掉的

AEDT 的命令列選項每一版拼法不太一樣。工具是照公開文件產生的，
沒辦法替客戶手上那一版背書——**猜錯的批次檔會直接失敗，比沒有還糟**。

`verify-batchoptions.cmd` 會列出那一版真正支援的選項。對過之後再把
`run-batch.cmd` 的註解解開。

### 為什麼沒有產生 .acf

`.acf` 的欄位結構沒有公開規格。猜出來的檔案匯入之後可能**看起來成功，
實際上套了錯的設定**——那比沒有 acf 更難查。

正確做法：在 AEDT 介面裡設好一次然後匯出，之後每台匯入同一份。

---

## 工具不會做的事

- 不關防火牆（只加「同網段可以進來」的規則）
- 不保存、不記錄、不傳送密碼（密碼只進 Intel MPI 自己的視窗）
- 不自動開始求解
- 不關掉也不打開 AEDT

---

## 先問客戶：串機划不划算

**兩台一起算不一定比一台快。**

DDM 這種切開模型分給多台的做法，在一般的千兆網路上**常常比單機還慢**——
機器之間傳資料的時間吃掉了多出來的算力。

而且核心數是這樣算的：

| 4 個 HPC Pack 怎麼配 | 總核心數 |
|---|---|
| 全部集中在 1 台 | 516 |
| 分給 2 台（各 2 個） | 72 |
| 分給 4 台（各 1 個） | 48 |

**攤到愈多台，總核心數愈少。** 所以會選擇分散，通常是因為
**單台記憶體塞不下**，不是為了核心數。

這件事最好在動手前就讓客戶知道。
