AEDT 2026 R1 兩台電腦串機

今天內部測試、明天客戶端操作皆可使用

適用：兩台 Windows 工作站，未使用 Windows HPC Scheduler

正確路線：Electromagnetics RSM ＋ Intel MPI ＋ AEDT Machine List
準備1．確認2．RSMGUI ①GUI ②GUI ③GUI ④GUI ⑤ 修復求解故障驗收

開始前只要準備這些

項目要求
Windows兩台使用相同版本與更新層級。
AEDT兩台安裝 AEDT 2026 R1，而且安裝路徑相同。
RSM安裝 Electromagnetics RSM。它不是 Ansys Remote Solve Manager。
MPI使用 AEDT 支援的相同 Intel MPI。一般兩台工作站不要選 Microsoft MPI。
權限使用實際執行 AEDT 的帳號開啟 GUI；只有按「套用完整修復」時會跳出系統管理員權限確認。
測試模型使用幾分鐘內能完成的小模型複本。
額外套件不用安裝任何額外套件，也不用輸入命令。
不要做：不要關閉防毒、不要永久關閉防火牆、不要修改 LocalAccountTokenFilterPolicy、不要使用 taskkill。

1確認兩台電腦名稱與版本

只開 GUI，不要開命令視窗。

  1. 在兩台電腦上找到解壓縮後的 Run-MpiToolkit-GUI.bat。
  2. 雙擊該檔案開啟 GUI，不需要輸入任何指令。
  3. 若出現「使用者帳戶控制」，按「是」。
  4. 切到「① 節點檢查」。畫面上方會顯示本機電腦名稱。
  5. 互相記下兩台顯示的名稱。以下範例稱為 WS01 與 WS02。
Windows、AEDT 與安裝路徑是否一致，稍後由 GUI 自動檢查。

2啟動並註冊 RSM

  1. 兩台都從 Windows「開始」搜尋並執行 Register with RSM。
  2. 看到註冊完成後按「確定」。
  3. 回到已開啟的 GUI。RSM 服務與 TCP 32958 會在節點檢查時自動確認。
通過：GUI 報告顯示 RSM 正在執行，而且 TCP 32958 正常。
若公司改過 RSM Port，AEDT Remote Analysis 與兩台 RSM 必須使用同一個值。

3在兩台執行串機檢查

C:\AnsysWork\MpiToolkit 不是 Ansys 預先建立的資料夾。兩台電腦都要自行建立，再把收到的 ZIP 全部解壓縮到這裡；「完整工具」不是指單一檔案。

  1. 在 ZIP 上按右鍵，選擇「內容」。如果看得到「解除封鎖」，請勾選後按「確定」。
  2. 開啟檔案總管，在 C:\ 建立 AnsysWork，再於其中建立 MpiToolkit。
  3. 把 ZIP 內的全部檔案解壓縮到 C:\AnsysWork\MpiToolkit。
  4. 確認資料夾內有 START_HERE.html、Run-MpiToolkit-GUI.bat 與 MpiToolkit-GUI.ps1。其他支援檔案不要移動或改名。
若公司權限不允許在 C:\ 建立資料夾，可用檔案總管改建在 D:\AnsysWork\MpiToolkit。
所有 Ansys 工作路徑與檔名都只能使用英文字母、數字、底線或連字號，不要包含中文。

直接使用 GUI

  1. 雙擊 Run-MpiToolkit-GUI.bat 開啟 GUI。
  2. 若出現「使用者帳戶控制」，按「是」。
  3. 在「① 節點檢查」輸入案件編號。兩台必須填完全相同的值。
  4. 「對端電腦名稱」填另一台電腦的 hostname。
  5. 模式選擇 DDM；報告資料夾可直接使用預設值，或按「瀏覽…」選擇。
  6. 按「開始節點檢查」，等待底部顯示「完成：節點檢查」。
  7. 按「開啟輸出資料夾」，確認有 *.node.json。
  8. 另一台用相同步驟執行，但「對端電腦名稱」要改填第一台。
不用輸入命令：GUI 會在背景完成檢查，使用者只要填欄位並按按鈕。

確認工具執行完成

  1. 畫面最後應顯示報告已產生，且沒有紅色的腳本錯誤。
  2. 在兩台分別開啟 C:\AnsysWork\MpiToolkit\reports_raw。
  3. 確認每台都有一個檔名以 AedtCluster_ 開頭、以 .node.json 結尾的檔案。
  4. 不要修改或用 Word 另存這個 JSON；下一步要直接複製原始檔案。
通過：兩台有相同 Windows、AEDT 與 Intel MPI；RSM 執行中；TCP 32958 為 OK；temp 路徑相同且皆為本機磁碟。
Intel MPI 的帳密註冊由 GUI「⑤ 連線修復」執行；不需要自行輸入 mpiexec 命令。

4把兩台報告放在一起彙整

  1. 選擇其中一台作為彙整電腦，例如 WS01。
  2. 在該台建立 C:\AnsysWork\MpiToolkit\merge_input。
  3. 從 WS01 的 reports_raw 複製 WS01 的 *.node.json 進去。
  4. 使用公司允許的網路分享或 USB，把 WS02 的 *.node.json 複製到同一個 merge_input。
  5. 確認資料夾內剛好有本次兩台電腦各一個 .node.json，不要混入舊案件檔案。
  6. 開啟 GUI 的「② 彙整報告」，按「瀏覽…」選擇 merge_input 與輸出資料夾。
  7. 按「開始彙整」，完成後按「開啟輸出資料夾」，閱讀最新的 .txt。

完成後開啟 C:\AnsysWork\MpiToolkit\merged_raw，先閱讀最新的 .txt 彙整報告。

通過：沒有「案件編號不一致」、「作業系統版本各機不同」、「沒有共通 AEDT」、「RSM 沒有執行」、「沒有共同 MPI」或「連線測試失敗」等【確定】項目。

5GUI ③：建立串機設定

這一步一定要做。彙整通過後，不要直接跳到 AEDT。

  1. 切到 GUI 的「③ 建立串機設定」。
  2. 在「節點 JSON 資料夾」按「瀏覽…」，選擇放有兩台 *.node.json 的 merge_input。
  3. 在「AEDT 小模型複本」按「瀏覽…」，選擇今天要測試的 .aedt 檔案。
  4. 「設定輸出資料夾」使用預設的 cluster_config，或按「瀏覽…」選擇其他 ASCII 路徑。
  5. 初次測試使用 Tasks＝1、Cores＝4、RAM＝90％。
  6. 按「建立串機設定」。
  7. 等待下方顯示「完成：產生設定檔」。
  8. 按「開啟輸出資料夾」，確認有 machines.txt、verify-batchoptions.cmd 與 待辦清單.txt。
通過：machines.txt 內有兩台電腦，而且沒有任何一台被標示為排除。
若按鈕拒絕建立，先回到「② 彙整報告」處理所有【確定】問題，不要勉強跳過。

6GUI ④：套用到 AEDT 並驗證

  1. 切到 GUI 的「④ 套用與驗證」。
  2. 按「驗證命令選項」，等待兩個 AEDT Help 視窗依序開啟；看完第一個並關閉後，才會出現第二個。
  3. 按「開啟 AEDT 小模型」。
  4. 在 AEDT 選擇 Tools ＞ Options ＞ HPC and Analysis Options。
  5. Options 頁設定 MPI Vendor = Intel。
  6. MPI Version 選 Default，或兩台共同安裝的版本。
  7. 新增或複製 Analysis Configuration，再按 Edit。
  8. 在 Machines 頁加入兩台電腦，各設 4 Cores、RAM 90％，並勾選 Enabled。
  9. 選取兩台並按 Test Machines。
通過：Test Machines 對兩台都沒有連線或註冊錯誤。
Test Machines 通過不等於串機完成。仍須跑真正的小模型。

7跑兩次小模型

7.1　先跑單機雙程序

  1. 只選 WS01，但配置兩個 process／task。
  2. 開始求解並確認完成。

7.2　再跑 WS01＋WS02

  1. 切換成含兩台的 Analysis Configuration。
  2. 使用與明天相同的求解類型。明天跑 DDM，今天就必須測 DDM。
  3. 開始求解。
  4. 在兩台工作管理員確認都有 solver process，CPU 或記憶體有活動。
  5. 查看 Messages、Solution Profile 或 batch log，確認兩台節點與實際 distribution type。
  6. 確認求解完成，並與單機主要結果比較。
真正通過：兩台都有求解程序＋記錄顯示兩台節點＋求解完成＋主要結果合理一致。
雙機比單機慢不一定是錯誤。小模型及 DDM 容易被網路延遲抵銷。

GUI ⑤：TEMP 不一致或求解卡住時修復

只有節點／彙整報告顯示 TEMP 不一致，或求解卡在 Determining memory availability 時才執行。

  1. 兩台都開啟 GUI，切到「⑤ 連線修復」。
  2. 「共同暫存路徑」保持 C:\AnsysWork\AedtTemp。兩台必須完全相同，但各自建立在本機磁碟。
  3. 「對端電腦名稱」填另一台電腦名稱。
  4. 按「套用完整修復（管理員）」。
  5. Windows UAC 出現時按「是」。不需要輸入任何指令。
  6. 看到「完整修復完成」後，在另一台重複相同步驟。
  7. 按「註冊 MPI 帳密並驗證」。
  8. Windows 帳密視窗使用預設帳號，輸入目前登入 Windows 的密碼。網域帳號格式為 Domain\user；不同網域且兩台已建立相同本機帳密時可用 .\User。
  9. 看到「Intel MPI 帳密註冊完成，對端驗證成功」。兩台都各執行一次。
  10. 儲存工作，兩台都重新啟動 Windows，讓 TEMP、RSM 與 MPI 設定完整生效。
  11. 兩台回到「① 節點檢查」重新執行；再彙整一次，確認 TEMP 路徑相同。
修復內容：備份 default.cfg、建立可寫的本機 TEMP、統一 tempdirectory、啟動 RSM／Intel Hydra，並固定下列連接埠。
用途TCP 連接埠允許範圍
RSM32958網域／私人網路的本機子網路
AnsoftCOM55000–55499網域／私人網路的本機子網路
Intel MPI55500–55999網域／私人網路的本機子網路
Intel Hydra依本機服務自動偵測，通常為 8680網域／私人網路的本機子網路
備份放在工具內的 repair_backup；結果放在 repair_reports。修復只新增／更新工具專用的允許規則，不會關閉 Windows 防火牆，也不會更改 hosts。
密碼安全：GUI 使用 Windows 的密碼遮罩視窗，密碼只透過標準輸入交給 Intel MPI，完成後立即清除；不放進命令列，不寫入報告或檔案。

失敗時照這張表處理

症狀先檢查
找不到遠端 RSMRSM 是否 Running、是否 Register with RSM、TCP 32958、兩邊 Port。
Test Machines 失敗主機名稱解析、Windows／AEDT 版本與路徑、RSM 註冊、防火牆例外。
只有 WS01 在算Configuration 是否含 WS02、setup 是否允許該 distribution type、模型是否太小。
DSO 成功但 DDM 失敗DSO variations 可能沒用 MPI。檢查 Intel MPI、Hydra、MPI Port 與安裝路徑。
MPI 啟動失敗Intel MPI 版本是否相同、AEDT 是否選 Intel，並於 GUI「⑤」重新執行「註冊 MPI 帳密並驗證」。
卡在 Determining memory availability先用 Cancel Analysis；再於兩台執行 GUI「⑤」的完整修復與 MPI 帳密驗證，完成後重新啟動兩台 Windows。
停在 ABORTING等待乾淨取消。不要用 taskkill；確認遠端 HFSS／HPC 授權已歸還後再重試。
其他求解卡住查看 Messages、Profile 與 log。使用 Cancel Analysis，不要用 taskkill。
防火牆：正式設定保持啟用並加入例外。暫時停用只用來隔離特定問題，測完立即恢復。
